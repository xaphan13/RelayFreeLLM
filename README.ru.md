# RelayFreeLLM

> **Один эндпоинт. Больше бесплатного ИИ, чем у любого отдельного провайдера. Меньше проблем с rate limit'ами.**

Для ИИ-ассистентов, работающих с кодом: прочитайте AGENTS.md и папку docs/ перед изучением исходного кода — это единый источник истины, который избавит от слепого обхода всего репозитория.

Не хотите платить $$ в месяц за использование ИИ-моделей? RelayFreeLLM — это open-source шлюз, который объединяет **несколько провайдеров с бесплатными тарифами** в единый API, совместимый с OpenAI — так вы получаете в совокупности больше бесплатного инференса с автоматическим переключением при сбоях.

```python
# Ваш существующий код работает. Просто поменяйте URL.
client = OpenAI(base_url="http://localhost:8000/v1", api_key="fake")
```

**Gemini · Groq · Mistral · DeepSeek · NVIDIA · Cerebras · Cloudflare · Ollama**

Никаких изменений в коде. Никакой логики повторов. Никаких ошибок 429, ломающих ваше приложение.

## Проблема бесплатных тарифов → Решение RelayFreeLLM

```
❌ Groq уперся в rate limit → Ваше приложение падает   ✅ Gemini не сработал → Автоматически пробуем Groq
❌ Квота Gemini исчерпана → Пользователь видит ошибку  ✅ Один провайдер недоступен → Трафик уходит к другим
❌ Смена провайдера → Переписывание интеграции          ✅ Один API для всех → Совместим с OpenAI
❌ Тестирование 5 провайдеров → 5 разных SDK           ✅ Больше провайдеров = Больше пропускной способности
```

## Админ-панель

Управляйте всем из браузера. Админ-панель по адресу [`http://localhost:8000/admin`](http://localhost:8000/admin) предоставляет визуальный интерфейс для управления лимитами моделей провайдеров и просмотра статистики использования в реальном времени — не нужно вручную редактировать JSON-файлы или перезапускать сервер.

### Вкладка Limits

- **Провайдеры** отображаются в виде сворачиваемых карточек, каждая со своими моделями в редактируемой таблице.
- **Inline-редактирование любого поля**: имя модели, тип (text/coding/image и т.д.), масштаб (large/medium/small), максимальная длина контекста и все 7 значений rate limit (запросов/токенов в секунду/минуту/час/день).
- **Добавление/удаление** моделей у провайдера, а также добавление/удаление целых провайдеров.
- **Save** записывает изменения в `provider_model_limits.json` и горячо перезагружает трекер rate limit'ов — перезапуск сервера не требуется.

### Вкладка Usage

- **Сводные карточки** показывают суммарные запросы, токены промпта, токены ответа и общее число токенов по всем провайдерам.
- **Разбивка по провайдерам** — таблицы с индивидуальным использованием каждой модели.
- **Reset Stats** обнуляет все счётчики в `usage_stats.json` с подтверждением.
- Данные автообновляются каждые 30 секунд.

Все данные хранятся в JSON-файлах — база данных не требуется.

## Чат-интерфейс

Полноценный веб-чат поставляется вместе с сервером по адресу [`/chat`](http://localhost:8000/chat).

### Возможности

- **Стриминг ответов** — посимвольный вывод в реальном времени
- **Атрибуция провайдера** — видно, какой провайдер/модель обработал каждый ответ
- **История диалогов** — сохранение чатов в браузере (`localStorage`) или на сервере (опционально)
- **Управление диалогами** — боковая панель с поиском, переименованием, копированием, удалением
- **Редактирование и удаление сообщений** — исправление опечаток или удаление ненужных веток посреди диалога
- **Загрузка изображений** — выбор файла, вставка, drag-and-drop; изображения отображаются прямо в сообщениях (клик для увеличения)
- **Маршрутизация по намерению** — переключение моделей через выпадающий список (`meta-model` или конкретный `Provider/Model`)
- **Тёмная/светлая тема** — переключение в шапке, предпочтение сохраняется

### Хранилище

По умолчанию диалоги сохраняются в `localStorage` браузера. Переключитесь на **Server**-хранилище через выпадающий список в шапке, чтобы хранить диалоги в `conversations.json` на диске — переживает сброс браузера и доступно с разных устройств с одним device ID.

## Как работает маршрутизация

### Выбор по намерению (Intent-Based Selection)
```json
{"model": "meta-model"}                              // Любой провайдер, выбирается следующий доступный
{"model": "meta-model", "model_type": "coding"}      // Любая coding-модель
{"model": "meta-model", "model_scale": "large"}       // Только крупные модели
{"model": "meta-model", "model_name": "deepseek"}     // Предпочтение моделям DeepSeek
{"model": "Gemini/gemini-2.5-flash"}                  // Конкретный провайдер/модель
```

### Автоматическое переключение (Failover)
```
Запрос → Groq (rate limit)
        → Активируется circuit breaker (60с кулдаун)
        → Повтор → Gemini
        → Повтор → Mistral
        → Успех ✓
```

### Маршрутизация с учетом изображений

Когда сообщение пользователя содержит части контента `image_url` (как определено в спецификации OpenAI Chat Completions), диспетчер автоматически ограничивает выбор моделями с поддержкой vision:

- **Маршрутизация meta-model** — во время выбора провайдера/модели рассматриваются только модели с `modality: "vision"` в реестре.
- **Явная маршрутизация** — если пользователь явно запросил text-only модель (например, `nvidia/minimaxai/minimax-m2.7`), диспетчер сначала ищет vision-модель у того же провайдера (например, `nvidia/moonshotai/kimi-k2.6`), затем откатывается к vision-модели любого провайдера. Если таких нет, возвращается понятная ошибка.

Это поведение управляется полем `modality` для каждой модели в `provider_model_limits.json`. Модели без поддержки изображений остаются доступными для text-only запросов.

### Единый стиль ответов
Несмотря на переключение между провайдерами, каждый ответ унифицируется:
- **Инъекция стилевой директивы** — универсальная директива добавляется к каждому системному промпту
- **Нормализация ответов** — убирает «As an AI...», «Certainly!», чинит JSON, стандартизирует markdown

Инъекцию стандартного системного промпта можно отключить per-request, отправив заголовок `X-Use-ServerSide-System-Prompt: false`. См. [Поддержка агентных фреймворков](#поддержка-агентных-фреймворков) ниже.

## Расширенные возможности

### Привязка сессии (Session Affinity)
Передайте `X-Session-ID: user-123`, и шлюз закрепит этого пользователя за одним провайдером. Если провайдер падает, сессия автоматически мигрирует.

### Поддержка агентных фреймворков
Агентные фреймворки (LangChain, AutoGen, CrewAI) управляют собственным системным промптом и историей диалога. Чтобы шлюз не инжектил свой стандартный промпт и не перестраивал массив сообщений, отправьте заголовок:

```
X-Use-ServerSide-System-Prompt: false
```

Поведение при `false` (либо per-request заголовок, либо серверный дефолт в `settings.json`):

- Массив `messages` клиента передаётся дословно, сохраняя порядок сообщений и роли (включая роли `tool` и `function` в будущем).
- Никакой серверный `STANDARD_SYSTEM_PROMPT` или стилевая директива не инжектируется.
- Собственное системное сообщение клиента (если есть) используется без дополнений.
- Если клиент не отправил системное сообщение, оно не отправляется и провайдеру.

Установите серверный дефолт в `settings.json`:
```json
{
  "routing": {
    "use_server_side_system_prompt": false
  }
}
```

> **Примечание:** Для полной точности порядка сообщений клиента используйте это вместе с `CONTEXT_MANAGEMENT_MODE=static` в `settings.json` — режимы вроде `reservoir` и `adaptive` могут переупорядочивать или суммировать контекст, когда диалог превышает бюджет токенов.

### Управление контекстом многоходовых диалогов
| Режим | Поведение |
|------|----------|
| **Static** | Хранит последние N сообщений дословно. |
| **Dynamic** | Подстраивает окно контекста на основе реального использования токенов. |
| **Reservoir** | Недавние сообщения дословно + экстрактивная сводка более старой истории. |
| **Adaptive** | Определяет coding vs chat диалоги и переключает стратегию. |

Режим Reservoir использует **алгоритм TF-скоринга** для выявления самых информативных предложений, применяет позиционный сдвиг для тематичности и жадно отбирает сегменты в рамках бюджета токенов — без обращений к LLM.

## Справочник API

### `POST /v1/chat/completions`
| Параметр | Тип | Описание |
|-----------|------|-------------|
| `model` | string | `"meta-model"` для авто-маршрутизации или `"provider/model"` для прямой |
| `messages` | array | Стандартный формат сообщений OpenAI. `content` принимает `str` или `list[{type, text, ...}]` для мультимодальных сообщений. |
| `stream` | bool | Включить SSE-стриминг |
| `model_type` | string | Фильтр: `text`, `coding`, `image`, `speech`, `embedding`, `moderation`, `ocr` |
| `model_scale` | string | Фильтр: `large`, `medium`, `small` |
| `model_name` | string | Совпадение по подстроке имени модели |

### `GET /v1/models`
```bash
curl http://localhost:8000/v1/models?type=coding&scale=large
```

> **Мультимодальный контент:** Поле `content` в каждом сообщении принимает либо plain string, либо список частей контента (например, `[{"type": "text", "text": "..."}, {"type": "image_url", "url": "..."}]`), согласно спецификации OpenAI Chat Completions. При наличии частей с изображениями диспетчер автоматически направляет запрос только к моделям с поддержкой vision (см. [Маршрутизация с учетом изображений](#маршрутизация-с-учетом-изображений)). Текстовые части «схлопываются» перед отправкой провайдерам, не поддерживающим структурированный контент.
>
> **Агентные фреймворки:** Чтобы передать массив `messages` клиента дословно без серверной инъекции системного промпта, установите `X-Use-ServerSide-System-Prompt: false`. См. [Поддержка агентных фреймворков](#поддержка-агентных-фреймворков).

### `GET /v1/usage`
```bash
curl http://localhost:8000/v1/usage
```

### Админ-эндпоинты

| Метод | Эндпоинт | Описание |
|--------|----------|-------------|
| `GET` | `/admin` | UI админ-панели |
| `GET` | `/admin/api/limits` | Получить текущие лимиты моделей провайдеров |
| `PUT` | `/admin/api/limits` | Обновить и сохранить лимиты (горячая перезагрузка сразу) |
| `GET` | `/admin/api/usage` | Получить статистику использования |
| `POST` | `/admin/api/usage/reset` | Сбросить статистику использования в ноль |

## Туториал: Создание бесплатного ИИ-CLI

**`chat.py`** — Терминальный чат-бот, использующий RelayFreeLLM с сохранением сессии:
```python
from openai import OpenAI
import readline

client = OpenAI(base_url="http://localhost:8000/v1", api_key="relay-free")
history = []

while True:
    user = input("\n> ")
    history.append({"role": "user", "content": user})
    r = client.chat.completions.create(model="meta-model", messages=history)
    reply = r.choices[0].message.content
    print(reply)
    history.append({"role": "assistant", "content": reply})
```

Запустите. Никаких счетов за API. Никаких rate limit'ов. В этом суть.

**`vision.py`** — Отправьте изображение; диспетчер автоматически направит запрос к vision-модели:
```python
import base64
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="relay-free")

with open("photo.jpg", "rb") as f:
    b64 = base64.b64encode(f.read()).decode("utf-8")

response = client.chat.completions.create(
    model="meta-model",
    messages=[{
        "role": "user",
        "content": [
            {"type": "text", "text": "What's in this image?"},
            {"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{b64}"}}
        ]
    }]
)
print(response.choices[0].message.content)
```

Запустите оба. Никаких счетов за API. Никаких rate limit'ов.
